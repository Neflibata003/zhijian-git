# 纸笺 Git 性能报告

## 测量环境

| 项 | 值 |
|---|---|
| CPU / 内存 | Intel Core i9-14900HX / 15.6 GB |
| 系统 | Windows 11 10.0.26100 |
| WebView2 | 154.0.4258.37 |
| Git | 2.54.0.windows.1 |
| 程序 | Release 构建，`paper-git.exe` 3.6 MB，安装包 3.05 MiB |

## 统计口径

- 统计对象：主进程 `paper-git.exe` + 它启动的全部 `msedgewebview2.exe` 子进程（共 7 个）。
- **私有工作集**（`\Process V2(*)\Working Set - Private`）为主指标，不含共享页面；**工作集**含共享的系统 DLL 页面，会明显偏大，仅供参考；峰值为各进程峰值之和，同样仅供参考。
- 单位 MB，来自单台机器，不代表其他机器。

## 结果

### A. 干净条件（不开调试端口，启动后稳定 75 秒，连续三次读数）

| 场景 | 私有工作集 | 工作集（含共享） |
|---|---|---|
| 无项目 | 约 70–85 MB | 约 394–400 MB |
| 打开小型仓库（5 个文件） | 约 92–95 MB | 约 418–421 MB |

达到了“100 MB 左右或以下”的目标。

### B. 压力场景（测试脚本通过调试端口驱动，读数偏高且波动大）

| 场景 | 结果 |
|---|---|
| 冷启动到可操作 | 约 0.58–0.64 秒（三次：576 / 577 / 638 ms） |
| 大仓库（1 万条历史 + 5000 个未跟踪文件）浏览期间，私有工作集峰值 | 142 MB（一次）/ 223 MB（另一次） |
| 大仓库浏览后回到空闲 | 221 MB（一次） |
| 之后连续切换项目 40 次并稳定 | 133 MB / 165 MB（两次） |
| 最小化 30 秒的 CPU | 0 s / 0.29 s |

说明：
- 调试端口本身会增加内存，且两轮测量差异较大（无项目 85 vs 123 MB），所以 B 组只能当作量级参考。**大仓库场景超过了 150 MB 排查线**（峰值 142–223 MB），属于已知限制，尚未进一步优化。
- 大列表使用虚拟滚动，DOM 中同时只有可视区附近的行；历史每页 50 条。
- 大仓库浏览后内存没有回落到初始值：WebView2 的渲染进程会保留已分配的内存，连续切换后有所回落（221 → 133/165 MB），但没有做更深入的释放分析。

### C. 空闲 CPU

| 条件 | 进程树 CPU |
|---|---|
| 启动 2 分钟后、无项目、20 秒窗口（无调试端口） | 约 0.02 s / 20 s（≈0.1% 单核） |
| 刚启动约 30–40 秒内 | 有明显的启动后活动（约 3–4 秒 CPU / 15 秒） |

- 空闲时应用不调用 Git：在小型和大型仓库上各观察 12 秒，未发现 git 子进程（测量脚本对该项的输出不完整，属弱证据）。
- **发现并修复**：曾出现空闲 CPU 偏高。A/B 测试显示是全屏“纸张噪点”叠层与阴影/过渡在软件渲染下持续重绘。关闭 GPU 合成后该问题在 2 分钟稳定后消失；但启动后前一两分钟仍有可见的渲染活动。若需更彻底，可去掉噪点叠层（这会牺牲一点纸张质感）。

### D. 与 CC Switch 的参考对比（同一口径、同一台机器、同一时刻）

| 应用 | 进程数 | 私有工作集（空闲） |
|---|---|---|
| CC Switch（当前正在运行） | 7 | 约 144 MB |
| 纸笺 Git（无项目） | 7 | 约 70–85 MB |

**注意**：两个应用功能和工作负载完全不同，CC Switch 当时的界面状态、运行时长未知，此对比只说明在这台机器上的空闲读数，不能说明谁的架构更省。

## 已采取的低内存措施

- Tauri + 系统 WebView2，无 Chromium；发布版 `opt-level="s"`、LTO、`strip`、`panic="abort"`。
- WebView2 参数：`--disable-gpu`（实测私有工作集由约 125 MB 降至约 90 MB，同时空闲 CPU 明显下降）。
- 文件列表、历史列表、追溯表使用虚拟滚动；历史分页 50 条；差异按选中文件加载，超过 512 KB 需手动继续。
- 文件监听仅针对当前项目，限制目录数并 650 ms 防抖；无轮询。
- Git 输出上限 16 MB，超时可取消，切换项目后忽略过期结果。

## 已知限制

- 大仓库（数千文件 + 上万提交）下内存超过 150 MB。
- 内存与 CPU 数据来自单机、少量次数，波动明显，请视为量级而非保证。
- 关闭 GPU 合成是为了降低内存与空闲 CPU，大窗口滚动的流畅度未做专门评测。
